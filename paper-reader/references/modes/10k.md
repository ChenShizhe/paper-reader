# 10-K mode

10-K mode targets primary SEC Form 10-K filings — the canonical U.S. public-company annual disclosure. Input is typically a born-digital PDF downloaded from SEC EDGAR, or inline-XBRL HTML pulled from the same source. A common local naming convention is `<TICKER>-10K-FY<YYYY>.pdf`. Output is a 14-section summary, per-Item notes, and a claims sidecar using 10-K-appropriate claim types.

Related filings — 10-Q quarterly reports, DEF 14A proxies, 8-K current reports, and earnings transcripts — share the Item-boundary or event-boundary segmentation pattern but differ in structure; they will have their own dedicated modes in future proposals.

## When to use

| Input shape | Mode |
|---|---|
| Primary SEC Form 10-K filing | `10k` |
| Analyst commentary **about** a 10-K | `simple` (source type `sell-side-note` or `rating-action`) |
| Academic research paper | `paper` |
| Book-length institutional report | `book` |
| Sell-side value-chain exhibit | `chain_map` |

## Invocation

```bash
python3 scripts/run_pipeline.py \
  --mode 10k \
  --cite-key <TICKER>_10k_FY<YYYY> \
  --ticker <TICKER> \
  --source-format <pdf|html|text> \
  --source-path <path-to-10-K-source> \
  --filing-metadata <path-to-metadata.json> \
  --paper-bank-dir <PAPER_BANK>/<cite_key> \
  --vault-root <VAULT_ROOT>
```

`--ticker` is required; downstream consumers (e.g., knowledge-maester's `ingest_ticker.py --mode append-thesis`) key their vault writes by ticker.

`--filing-metadata` is an optional JSON file populated from the filing header or an upstream metadata fetcher:

```json
{
  "ticker": "NVDA",
  "company_name": "NVIDIA Example Corp.",
  "fiscal_year": "2024",
  "period_end": "2024-01-28",
  "filed": "2024-02-21",
  "cik": "0001045810",
  "accession_number": "0001045810-24-000000",
  "source_format": "pdf",
  "amendment": "10-K"
}
```

Fields are written through verbatim to the summary frontmatter.

## Pipeline steps

1. **Translate.** `pdf` sources route through PyMuPDF (10-Ks are born-digital since 2000s). `html` sources route through `translate_10k_html.py`, which strips iXBRL namespace tags while capturing numeric facts to `_xbrl_tags.json`, normalizes Item headings as `## Item <N>. <Title>`, and emits `translated_full.md`. `text` sources are wrapped in a markdown container.
2. **Segment (10-K specific).** `segment_10k.py` regex-detects `Item <N>. <title>` heading boundaries (`^(#{1,6}\s+)?Item\s+(\d{1,2}[A-Z]?)\s*[.:\-–—]\s*(.+?)$`). Produces one segment file per present Item at `segments/item-<N>.md` plus a manifest with `segmentation_version: "10k_v1"`. Incorporation-by-reference language in Items 10–14 is detected and recorded.
3. **Comprehension (3 parallel subagents).** `comprehend_paper.py --mode 10k` dispatches three subagents in parallel:
   - **positioning**: Items 1 (Business), 1A (Risk Factors), 1C (Cybersecurity). Produces Company Snapshot, Business and Segments, Priority Risk Factors.
   - **financial**: Items 6 (Selected Financial Data), 7 (MD&A), 7A (Market Risk Disclosures), 8 (Financial Statements and Notes). Produces MD&A Synthesis, Segment Performance, Financial Position, Cash Flow Quality, Notes Highlights, Non-GAAP and KPI Reconciliation.
   - **risk_forward**: Items 9A (Controls and Procedures), 9B (Other Information), plus forward-looking prose across MD&A. Produces Controls and Governance, Evolving-Topic Coverage, Forward-Looking Statements.

   Each subagent writes a structured JSON file to `<paper-bank>/_10k_<subagent>.json` with `sections` (section-name → prose) and `claims` (permitted claim types).
4. **Summarize.** `summarize_paper.py --mode 10k` merges the 3 subagent JSONs against the segment manifest + filing metadata, produces the 14-section summary body at `<vault>/papers/<cite_key>.md`, writes per-Item notes at `<vault>/papers/<cite_key>/item-<N>.md`, and emits the claims sidecar at `<vault>/claims/<cite_key>.json`.
5. **Validate.** `validate_10k_mode.py` checks frontmatter completeness, all 14 sections present and ordered, per-Item notes for every Item in `items_present`, claims sidecar uses only permitted types, and that `source_anchor.locator` parses as `<N>-<section-heading>`.

## Output summary schema

### Frontmatter

```yaml
---
cite_key: <TICKER>_10k_FY<YYYY>
ticker: <TICKER>
company_name: <string>
filing_type: 10-K
fiscal_year: <YYYY>
period_end: <YYYY-MM-DD>
filed: <YYYY-MM-DD>
cik: <string>
accession_number: <string>
source_format: pdf | html | text
mode: 10k
word_count: <int>
items_present: [1, 1A, 1C, ...]
items_incorporated_by_reference: [10, 11, 12, 13, 14]
amendment: 10-K | 10-K/A
---
```

### 14 summary sections (in order)

1. `## Company Snapshot` — one-paragraph synthesis answering the two anchor questions (what drives profits; what drives future growth).
2. `## Business and Segments` — segment list with products/markets.
3. `## Priority Risk Factors` — top-ordered Item 1A risks with hypothetical-vs-realized language flags.
4. `## MD&A Synthesis` — period-to-period change narrative; known trends and uncertainties; critical accounting estimates with sensitivity.
5. `## Segment Performance` — per-segment revenue, margin, YoY change, reconciled to total.
6. `## Financial Position` — balance-sheet summary, liquidity, debt composition, leverage.
7. `## Cash Flow Quality` — operating CF vs. net income, capex trajectory, financing activity.
8. `## Notes Highlights` — highlights from key footnotes (tax, pension, derivatives, revenue recognition, segment, contingencies, subsequent events).
9. `## Controls and Governance` — Item 9A material-weakness status, auditor opinion, Part III governance highlights via DEF 14A cross-reference.
10. `## Non-GAAP and KPI Reconciliation` — management-defined KPIs, non-GAAP measures, reconciliation paths.
11. `## Evolving-Topic Coverage` — cybersecurity (Item 1C), AI materiality, climate, geopolitical, supply chain, labor. Present / absent / thin.
12. `## Textual-Analysis Flags` — placeholder section populated by T-009 textual-analysis screening (LM category densities, YoY deltas, CMN Item-1A cosine similarity). Empty or summary-only in the current MVP.
13. `## Forward-Looking Statements` — management guidance by segment and consolidated; disclosed assumptions.
14. `## Open Questions` — material topics raised but not resolved; cross-references to 10-Q / 8-K / earnings call.

### Per-Item notes

One file per canonical Item at `<vault>/papers/<cite_key>/item-<N>.md`. Present Items carry the segment body; incorporated-by-reference Items carry a stub with the reference pointer; absent Items carry a short absent stub.

### Claims sidecar

`<vault>/claims/<cite_key>.json` with permitted claim types:

- `methodology` — management's accounting-policy elections.
- `empirical` — line items and footnote quantifications.
- `projection` — forward-looking guidance with disclosed assumptions.
- `limitation` — critical-accounting-estimate sensitivity ranges.
- `data-availability` — Part III / DEF 14A pointers, exhibit references.
- `company-thesis` — segment-level operational narrative for ticker-profile ingestion.
- `supply-chain-fact` — supplier / customer concentration disclosures.

Rejected: `theorem`, `assumption`, `proofs`, `policy-recommendation`. The validator downgrades unrecognized types before write.

## Integration with knowledge-maester

10-K mode outputs are the primary source for per-ticker thesis-update blocks maintained by `knowledge-maester/scripts/ingest_ticker.py --mode append-thesis`. See `knowledge-maester-improvement/02-10k-summary-ingestion.md` for the input contract.

## Known MVP limitations

- **No textual-analysis screening yet.** The `## Textual-Analysis Flags` section is present in the schema but not auto-populated; a later proposal (T-009) adds Loughran-McDonald category densities and Cohen-Malloy-Nguyen Item-1A cosine similarity.
- **No cross-filing amendment linking.** 10-K/A amendments are treated as independent filings; amendment-to-original chaining is a future refinement.
- **No machine-readable XBRL sidecar.** Numeric iXBRL facts land in `_xbrl_tags.json` as a best-effort capture; a structured claims path for financial-statement line items is out of scope for the initial MVP.
